THE APPROVAL MODEL

An approval binds one exact payload, and burns once.

A simulated agent proposes refunds, customer messages, order address changes, and report exports. A team member signs in through NamoID Hosted Auth, inspects the request, and may edit it before deciding. Approving stores a SHA-256 hash of the canonical payload, the decider's server-derived NamoID subject, and a ten-minute expiry.

At execution the server re-hashes the current payload and compares it to the approved hash, so a changed amount, address, recipient, or destination is refused. The approval is then consumed atomically, so a replayed execution is refused too. Every allowed or blocked attempt is written to a redacted audit trail that carries hashes and reason codes, never raw payloads or tokens.
